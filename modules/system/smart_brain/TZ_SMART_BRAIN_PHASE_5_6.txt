====================================================
PHASE 5 — COIN PASSPORTS
====================================================

Goal:
Maintain long-term statistics per symbol.


LOCATION
--------

storage/passports/

Each symbol must have its own passport file:

storage/passports/BTCUSDT.json
storage/passports/ETHUSDT.json


PASSPORT STRUCTURE
------------------

Each passport must contain:

symbol

corridor_width_avg
volatility_avg

avg_mae
avg_mfe

avg_duration

winrate

trades_total
trades_won
trades_lost

speed_class

reliability_score

updated_at


EXAMPLE
-------

{
 "symbol": "BTCUSDT",

 "corridor_width_avg": 0.032,
 "volatility_avg": 0.012,

 "avg_mae": 0.006,
 "avg_mfe": 0.018,

 "avg_duration": 17,

 "winrate": 0.71,

 "trades_total": 150,
 "trades_won": 107,
 "trades_lost": 43,

 "speed_class": "fast",

 "reliability_score": 0.82,

 "updated_at": "2026-03-13T18:00:00Z"
}


PASSPORT ENGINE
---------------

File:

lib/coin_passport_engine.php


Responsibilities:

1. Ensure passport file exists for each symbol appearing in monitors.json

2. Load existing passport if present

3. Update passport statistics after each simulator cycle


DATA SOURCES
------------

monitors.json
simulator/closed.json


Passport update should include:

- updating trades_total
- updating winrate
- recalculating avg_mae
- recalculating avg_mfe
- recalculating avg_duration


MAE/MFE DEFINITIONS
-------------------

MAE = maximum adverse excursion

MFE = maximum favorable excursion


RELIABILITY SCORE
-----------------

Compute reliability_score as:

reliability_score =
winrate
× log10(trades_total + 1)
× corridor_width_avg


Clamp value between:

0 and 1


SPEED CLASS
-----------

Based on avg_duration:

avg_duration < 10  → fast
avg_duration < 30  → medium
else               → slow



UI REQUIREMENT
--------------

Coin Passports tab must display:

symbol
trades_total
winrate
avg_mae
avg_mfe
avg_duration
speed_class
reliability_score



====================================================
PHASE 6 — RISK ENGINE
====================================================

Goal:
Transform monitored opportunities into trade-ready signals
with adaptive risk parameters.


FILE
----

lib/risk_engine.php



INPUT
-----

monitors.json
passport data
profiles config


OUTPUT
------

storage/signals.json



SIGNAL STRUCTURE
----------------

Each signal must contain:

symbol

entry_zone_low
entry_zone_high

corridor_low
corridor_high
corridor_width

leverage
budget

stop_loss
take_profit

status


Example:

{
 "symbol": "BTCUSDT",

 "entry_zone_low": 62100,
 "entry_zone_high": 62580,

 "corridor_low": 62100,
 "corridor_high": 64500,

 "corridor_width": 0.038,

 "leverage": 6,
 "budget": 12.5,

 "stop_loss": 0.012,
 "take_profit": 0.028,

 "status": "waiting"
}



RISK ENGINE ALGORITHM
---------------------

For each monitor:

1. Load passport for symbol.

2. Load profile limits from:

config/profiles.php


3. Calculate leverage:

base_leverage =
passport.reliability_score
× profile.max_leverage

Clamp:

1 ≤ leverage ≤ profile.max_leverage



4. Calculate budget:

budget =
profile.budget
× passport.reliability_score

Clamp:

≤ profile.max_budget_per_coin



5. Calculate stop loss:

stop_loss =
corridor_width
× profile.stop_loss_range



6. Calculate take profit:

take_profit =
corridor_width
× profile.take_profit_roi



7. Skip monitor if:

passport.reliability_score < 0.15


8. Only generate signals if monitor status:

entry_zone



SIGNAL OUTPUT
-------------

Write signals to:

storage/signals.json



UI REQUIREMENT
--------------

Analyzer tab must show:

signals count
signal parameters

Dashboard must display signals card correctly.
