# Рыбалка — описание стратегии и технические характеристики

## Назначение
`Рыбалка` — выжидательная трендовая стратегия для поиска лимитных входов от уровня ликвидности.
Её смысл не в частой торговле, а в выборе редких, но структурно понятных точек входа после коррекции по тренду.

## Где применять
- **Криптофьючерсы**: в первую очередь ликвидные монеты.
- **Форекс**: валютные пары с долларом.
- Для первой безопасной реализации в системе рекомендуется использовать:
  - `universe_mode = manual_list` или `all`
  - приоритет ликвидным инструментам

## Таймфрейм
- **Только H4**.
- Ниже — слишком шумно.
- Выше — слишком грубо для этой стратегии.

## Тип стратегии
- **Безиндикаторная**.
- Основана на:
  - структуре рынка
  - истинных экстремумах
  - уровне ликвидности
  - входе лимитным ордером в сторону тренда

## Базовая логика стратегии

### 1. Определение структуры рынка
Сначала определяется рабочая структура:
- ближайший **истинный локальный максимум**
- ближайший **истинный локальный минимум**

Из этих экстремумов определяется текущая тенденция:
- **bullish** — искать только покупки
- **bearish** — искать только продажи
- **ranging / unknown** — сделок нет

Стратегия не торгует во флете и не работает против структуры.

### 2. Уровень ликвидности
Основной сетап строится по **3–4 последовательным барам H4**.
Уровень ликвидности определяется по зоне открытий/закрытий этих баров.

Практический смысл:
- в этой зоне предполагается наличие лимитных заявок крупного участника
- при возврате цены к этой зоне ожидается остановка и продолжение движения по тренду

### 3. Подтверждающий бар
После формирования 3–4-барного паттерна требуется подтверждение.
Для кодовой реализации используется правило:
- для **long** подтверждающий бар должен закрыться **выше** диапазона паттерна
- для **short** подтверждающий бар должен закрыться **ниже** диапазона паттерна

Если подтверждение прошло в противоположную сторону, уровень невалиден.

### 4. Направление входа
Сделка разрешена только в сторону трендовой структуры:
- bullish structure -> только **Buy Limit**
- bearish structure -> только **Sell Limit**

### 5. Вход
Вход всегда:
- **limit order**
- по рассчитанному **liquidity level**

Идея стратегии — не догонять цену, а ждать возврата к уровню.

### 6. Stop Loss
Stop Loss ставится:
- **не за сам паттерн**, а
- за **ближайший истинный экстремум**, который логически отменяет сценарий

То есть stop — структурный, а не произвольный.

### 7. Take Profit
TP строится от диапазона паттерна.

Базовая формула для реализации:
- `pattern_range = pattern_high - pattern_low`
- `tp = entry ± pattern_range * 4.0`

Практически это соответствует идее расширения примерно к `400%` диапазона.

### 8. Перевод в безубыток
BE trigger:
- после прохождения ценой расстояния, равного `1 x pattern_range`

То есть:
- `breakeven_trigger = entry ± pattern_range * 1.0`

## Технические характеристики для модуля `fish`

### Обязательные характеристики стратегии
Это часть идентичности стратегии и не должна свободно ломаться конфигом:
- timeframe: `H4`
- trading style: `trend only`
- entry type: `limit`
- level source: `3–4` барный liquidity pattern
- stop anchor: `nearest true structural extremum`
- take profit model: `pattern_range * 4.0`
- breakeven model: `pattern_range * 1.0`

## Что считается правильным поведением сканера
- сканер работает **по кругу**, а не один раз навсегда
- после полного цикла universe начинается новый цикл
- сигналы имеют срок жизни в **H4 барах**, а не в минутах
- дубли по `symbol + side` должны резаться
- в финальном наборе сигналов должна оставаться одна лучшая идея на `symbol + side`

## Что считается правильным поведением бота
- бот работает только со **своими** сигналами и позициями `fish`
- ownership обязателен:
  - `owner_strategy = fish`
  - `owner_signal_id`
  - `owner_order_id`
  - `owner_position_id`
- после fill должен происходить переход:
  - `order accepted -> order filled -> position opened -> SL/TP attached`
- smoke/live state должны быть изолированы
- старые smoke-ордера не должны блокировать live

## Что нельзя ломать при модификации стратегии
При дальнейших изменениях нельзя без отдельного решения менять:
- H4 на другой таймфрейм
- limit entry на market entry
- трендовую логику на контртренд
- stop от структурного экстремума на случайный stop
- TP 4x на произвольный TP без явной новой версии стратегии

Если эти вещи меняются, это уже не просто модификация `Рыбалки`, а новая версия или новая стратегия.

## Что ещё нужно держать под контролем
Для дальнейших улучшений нужно явно помнить, что стратегия чувствительна к:
- качеству определения истинного экстремума
- допуску при построении liquidity level
- корректности confirming bar
- возрасту уровня/сигнала
- дублям по одному и тому же символу
- RR-геометрии

## Практический смысл для проекта
В проекте `fish` должен рассматриваться как:
- **отдельный strategy-module**
- со своим scanner
- своим bot runtime
- своим конфигом
- своим cron-cycle
- своей статистикой
- своим ownership

То есть:
- Brain = UI и управление
- Fish = стратегия как унитарная система
- общий Bybit/API core = транспорт и биржевой доступ

## Короткая формула стратегии
1. Найти H4 структуру.
2. Определить тренд.
3. Найти 3–4 барный liquidity pattern.
4. Подтвердить его правильным confirming bar.
5. Поставить limit order по уровню в сторону тренда.
6. Поставить stop за ближайший истинный экстремум.
7. Выставить TP = `4 x pattern_range`.
8. После `1 x pattern_range` перевести в BE.
9. Не держать старые и дублирующиеся сигналы.
